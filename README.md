# score-rebar-web

在浏览器里编辑**复声部**谱面，并保证"前端选择 / 后端接纳 / 谱面排版 / MusicXML 往返"
四者的**音乐时间一致**。不是 MusicXML 文本编辑器，也不做音频播放。

初始素材就是描述里的两小节、两个声部片段：上声部开头是三个八分音符组成的
3:2 三连音，接着是一个**跨小节延续的 G4**；下声部每小节一个 C3 长音。
两个声部用 `<backup>` 在同一小节内回到各自起点——导入时不会被当成一条顺序
音符列表。

## 核心思想：三个层次分离

| 层次 | 是什么 | 标识 |
|------|--------|------|
| **发声事件 SoundingEvent** | 一次"发声"：绝对节拍上的音/和弦/休止，以及它的实际时值 | `eventId`（稳定，重排不变） |
| **声部时间线 Voice** | 该声部由发声事件+休止从第 0 拍**无缝铺满**，无空隙无重叠 | `voiceId` |
| **显示片段 Slice / RenderNote** | 发声事件被小节线切开、再切成可雕版音符头后的**视觉片段**，片段之间用延音线连接 | `sliceId`（由事件+起止拍派生） |

关键点：

- **改拍号只改网格，不改声音。** 4/4→3/4 时，所有 `eventId` 的 `start/end`
  原样不动；变化的只是发声事件被切成几片、哪里出现延音线。三连音三个音的
  实际时值始终是每个 **1/3 拍**（连音记谱值是八分音符 1/2 拍，二者分开存储）。
- **多一片音符 ≠ 多一次发声。** 一个持续的音在 3/4 下是同一个 `eventId` 的
  三个 slice。点任意一片，选中的是**整个发声事件**（所有片段同时高亮），
  检查器显示的是事件层的开始/结束/实际时值，以及它由哪些显示片段构成。
- **每个声部独立重划。** 上声部重新划分不会把下声部的 C3 挤到别的时间。
- 所有时间用**精确有理数**（后端 `fractions.Fraction`，前端 `Q` 分数类），
  线上格式是 `"n/d"` 字符串，浏览器里三连音不会有浮点漂移。

## 编辑语义（真正改动声部时间）

- 选声部、选音符/休止、改音高、改实际时值、把事件移到同一声部的另一个时刻。
- 改音高不动时间；改时值会吸收/让出相邻**休止**；若会覆盖别的发声音则被后端
  **拒绝**（HTTP 422），不会悄悄抹掉音符。
- 移动事件：让出的位置补休止、目标休止被吸收，落点与发声音碰撞则拒绝。事件
  **身份 `eventId` 保留**。
- 被拒绝的编辑留在前端可继续修改，顶部黄/红条说明它与当前声部时间的关系，
  选中的事件不会丢。
- 缩放、翻页只改显示，不发请求、不碰模型。

## 确认状态（解决"图重排了但导出还是旧小节"）

每次被接纳的编辑都生成一个**不可变修订版本（revision）**，并在同一事务里把
三样东西一起写盘：

1. 规范 score 模型；
2. 由它派生的显示投影（bars/slices/tie/tuplet）；
3. 由它导出的 MusicXML。

前端每次请求带着它看到的 `baseRevision`；若已过期返回 **409 revision_stale**，
本次编辑不落库，前端可刷新到新状态且仍选中同一个 `eventId`。因此"下一次拿到
的谱面、选择对象、导出内容"必然属于同一个确认状态。修订以 JSON 文件持久化到
`data/scores/<scoreId>/`，重新打开能找回拍号、声部和编辑结果，不依赖浏览器
临时对象。

## MusicXML 往返

`music21` 只作为**读写库**（理解 `backup`、`divisions`、`time-modification`、
`tie/tied`）。真正的语义在本仓库的规范模型里：

- 导入：按 `<voice>`/part 拆声部，把 tie 链（start/continue/stop）合并成
  **一个**长发声事件；记录连音 actual/normal/unit。
- 导出：把显示片段按小节逐音符头输出，自动生成跨小节/小节内 `tie` 与
  `tied`，三连音输出 `time-modification` 与 tuplet 括号。

已验证：种子在 4/4 与改到 3/4 后，导出再重新导入，**发声音的起止拍与音高、
拍号完全一致**（见 `backend/tests`）。

## 运行

需要 Python 3.11、Node 20。

```bash
# 后端（首次会把 data/seed_musicxml/seed.xml 导入为 id=seed 的谱面）
pip install -r requirements.txt
python -m backend.serve            # http://localhost:8000

# 前端开发（热更新，/api 代理到 8000）
cd frontend
npm install
npm run dev                        # http://localhost:5173

# 或只构建一次，由后端在 / 托管构建产物
cd frontend && npm run build       # 然后访问 http://localhost:8000
```

第一屏就是可操作谱面：选片 → 在工具栏"从选中小节起改拍" → 看延音线/分片段
变化 → 检查器改音高/时值/移动 → 顶部"导出 MusicXML（本状态）" → 可重新导入
核对发声时间。

## 测试

```bash
python -m pytest backend/tests -q
```

覆盖：tie 链合并为单事件、三连音实际时值、声部独立、改拍不变发声、3/4 下
G4 切成三片且同 `eventId`、各小节被铺满、括号 start/continue/stop、改音高
保时间、移动重铺、碰撞拒绝不删事件、4/4 与 3/4 的导出/再导入一致、修订版本
陈旧 409 与拒绝 422 的 API 语义。

## 范围

音符、和弦、休止符、拍号、声部（独立时间线）、延音线、连音组。
不含歌词、演奏法库、多人协作、音频播放。

## 目录

```
backend/
  model.py       规范模型：Pitch/Duration/Tuplet/SoundingEvent/Voice/Score，有理数时间
  edits.py       不变量校验（声部铺满）+ 音高/时值/移动/拍号编辑
  notation.py    无小节模型 -> 小节网格/显示片段/音符头/tie/连音括号 的投影
  musicxml_io.py music21 导入导出（在规范模型上构建，不是替换 XML 标签）
  store.py       确认状态修订版本（原子写盘、乐观并发）
  app.py         FastAPI：import / 文档 / 改拍 / 事件编辑 / 导出 MusicXML
frontend/src/
  types.ts q.ts api.ts
  ScoreView.tsx  VexFlow 5 渲染（真实音符头、休止、tie、三连音括号、点击选择）
  App.tsx        工具栏、声部切换、事件检查器、改拍与编辑、拒绝/陈旧态
data/seed_musicxml/seed.xml   初始两小节双声部素材
```
